# tools — サイト点検の道具

## これは何か

サイト全体を機械的に点検して、崩れている箇所を一覧で出す道具です。

道具は主に3つあります。

| 道具 | すること | 時間 |
|---|---|---|
| `check_site.py` | HTMLの中身(文字列)を点検。構造・タイトル・匿名性・出典など | 数秒 |
| `check_browser.py` | 実際にブラウザで開いた表示結果を点検。画像切れ・はみ出し・JSエラー・押しづらいボタン | 数分 |
| `new_kiji.py` | 新しい記事の「入れ物」を作る。HTML一式+台帳+sitemapに一度で登録(使い方はファイル冒頭) | 一瞬 |
| `gikai.py` | 大洲市議会の会議録を年度をまたいで全文検索する。裏取りの一番の武器 | 初回数分・2回目以降は一瞬 |

### 会議録を検索する(`gikai.py`)

```powershell
python tools/gikai.py 松下寿                  # 全期間(2008年〜)から探す
python tools/gikai.py 新幹線 --from 2020      # 2020年以降だけ
python tools/gikai.py 空き家 --list           # ヒットした会議の一覧だけ
```

大洲市議会の会議録は平成20年ごろから全文が公開されていて、**新聞記事より情報量が多く、しかも消えません**。松下寿の記事では、市長の生の言葉(「青天のへきれき」)、新聞に載っていない数字(有効求人倍率0.39倍)、どこにも書かれていなかった事実(「昭和48年 大洲市企業誘致条例によって誘致」)がここから出てきました。

取ってきた会議録は `tools/_gikai_cache/` に貯めます(.gitignore済み。GitHubには上げません)。消しても次に取り直すだけです。

ふだんの点検は `check_site.py` だけで十分です。`check_browser.py` は、デザインやレイアウトを変えたあと・月次点検のときに走らせてください(初回のみ `pip install playwright` と `playwright install chromium` が必要)。アクセス解析への通信は自動でブロックするので、何度走らせても本物のアクセス数は汚れません。

これまで「太字を付け忘れた」「出典欄のクラスが抜けた」「タイトルを直したのに記事一覧だけ古いまま」といったミスが、何度も繰り返し起きていました。人が目で見て防ぐには数が多すぎるので、機械に見張らせることにしたものです。

**ファイルは一切書き換えません。読むだけです。** 何度走らせても安全です。

## 使い方

PowerShellで、このリポジトリのフォルダに入ってから打ちます。

```powershell
# まずリポジトリのフォルダへ移動する
python tools/check_site.py
```

数秒で結果が出ます。

### いろいろな走らせ方

| やりたいこと | コマンド |
|---|---|
| ふつうに点検する | `python tools/check_site.py` |
| 出典URLが生きているかも見る(数分かかる) | `python tools/check_site.py --urls` |
| 1つの記事だけ見る | `python tools/check_site.py --slug ozu-mirai-note` |
| 疑問形の見出しを一覧にする | `python tools/check_site.py --headings` |
| 点検器自体が壊れていないか確かめる | `python tools/check_site.py --selftest` |
| 結果をファイルに保存する | `python tools/check_site.py --json 結果.json` |

## 結果の読み方

```
  【構造】...................... OK
  【タイトル】.................. エラー 1件
  【匿名性】.................... OK
  【文字化け】.................. OK
  【出典】...................... エラー 9件
```

- **エラー** … 直した方がよいもの。読者に見える不具合か、決めたルールに反しているもの。
- **警告** … 見て判断するもの。直さなくても壊れません。

エラーがゼロなら、それは「もう見なくていい」という意味です。

## 何を見ているか

| 種類 | 中身 |
|---|---|
| 構造 | ヘッダー・出典欄・写真ブロック・スクリプトなど、必要な部品が揃っているか |
| タグ | `<div>` などの開き閉じが合っているか(合わないとレイアウトが崩れる) |
| 表 | 記事内の表がスクロール用の囲いに入っているか(無いとスマホで横にはみ出す) |
| タイトル | 記事の中の4か所と、記事一覧の台帳で、タイトルが一致しているか |
| 台帳 | 台帳にあるのにファイルが無い、という食い違いがないか |
| 匿名性 | 本名や勤務先が本文に出ていないか |
| 文字化け | 文字化け記号が混ざっていないか |
| 出典 | 2本以上あるか。すぐ消えるURLを使っていないか |
| スタイル | 見出し・太字が最低限あるか |
| 文体 | 大洲ノートが常体で統一されているか |
| リンク | `--urls` のとき、出典URLが本当に生きているか |

## 「OK」を信用してよいのか

点検器そのものが壊れていたら、何も見つけずに「OK」と言い続けてしまいます。それを防ぐのが自己診断です。

```powershell
python tools/check_site.py --selftest
```

わざと9か所壊したページを一時的に作って、全部検知できるかを確かめます。ここが通らないうちは、点検結果を信用しないでください。

サイトの作りを大きく変えたあとは、これを走らせてください。

## わざと見逃しているもの

- **`book/`(大洲と読書)が敬体なのは、わざとです。** 常体で統一する方針なのは大洲ノート(`eachnews/`)だけなので、book には常体チェックを掛けていません。
- **実在の地名や学校名が引っかかることがあります。**記事の内容として正当なものは、検査の対象から除外しています。除外の指定はリポジトリ外の語リストに書いてあります。

## 基準を変えたいとき

`check_site.py` の上のほうに、設定がまとまっています。

```python
MIN_SOURCES = 2   # 出典は2本以上
MIN_H2 = 2        # 見出しの最低数
MIN_STRONG = 1    # 太字の最低数
```

「出典は3本以上にしたい」と思ったら、`MIN_SOURCES = 3` に変えるだけです。クロコに「出典3本以上に変えて」と言ってもらっても構いません。
