# tools — サイト点検の道具

## これは何か

サイト全体を機械的に点検して、崩れている箇所を一覧で出す道具です。

道具は主に3つあります。

| 道具 | すること | 時間 |
|---|---|---|
| `check_site.py` | HTMLの中身(文字列)を点検。構造・タイトル・匿名性・出典など | 数秒 |
| `check_browser.py` | 実際にブラウザで開いた表示結果を点検。画像切れ・はみ出し・JSエラー・押しづらいボタン | 数分 |
| `new_kiji.py` | 新しい記事の「入れ物」を作る。HTML一式+台帳+sitemapに一度で登録(使い方はファイル冒頭) | 一瞬 |
| `gikai.py` | 大洲市議会の会議録を年度をまたいで全文検索する。裏取りの一番の武器 | 初回数分・2回目以降は一瞬 |
| `hook_check.py` | クロコが応答を終える直前に、いま触ったページだけを自動点検する(自分で叩く必要はない) | 一瞬 |
| `check_numbers.py` | 記事の数字が、その記事の出典に本当に載っているかを照合する | 初回数十分・2回目以降は数秒 |
| `ledger.py` | どの記事を、いつ、誰が、どのレベルで確認したかの台帳 | 一瞬 |

## 「この記事、チェックしたっけ?」に答える(`ledger.py`)

**記憶で答えないこと。** 台帳を見る。

```powershell
python tools/ledger.py show ozu-shakyo-kessan
```

```
  確認の記録: 2回
    ? 2026-08-08  人が読んで裏取り  notion:ガチ完了     ガチ完了
    ○ 2026-08-29  機械点検          check_site.py      問題なし
```

行頭の記号が肝です。

| 記号 | 意味 |
|---|---|
| ○ | 確認したときの本文と、いまの本文が同じ。**この確認はまだ有効** |
| × | 確認したあとに本文が変わった。**この確認はもう無効**。確認し直しが要る |
| ? | 確認した記録はあるが、そのときの本文が分からない(Notionから取り込んだ古い記録) |

「確認したのに、そのあと書き直したことを忘れる」のが一番こわいので、記事本文のハッシュを一緒に記録しています。**確認済みかどうかではなく、その確認がいまも生きているかを見る台帳です。**

| やりたいこと | コマンド |
|---|---|
| 全体の状況 | `python tools/ledger.py show` |
| 1記事の履歴 | `python tools/ledger.py show <スラッグ>` |
| 確認後に本文が変わった記事 | `python tools/ledger.py stale` |
| 人の確認がまだの記事 | `python tools/ledger.py todo --level human` |
| 確認したことを記録する | `python tools/ledger.py record <スラッグ> --level human --by opus --note "出典PDFの表まで確認"` |
| 機械点検の結果を記録する | `python tools/ledger.py import-site` |
| 数字照合の結果を記録する | `python tools/ledger.py import-numbers 結果.json` |

台帳の中身は `tools/check-ledger.json`。テキストなのでgitで履歴も追えます。

## 数字が出典に載っているか照合する(`check_numbers.py`)

```powershell
python tools/check_numbers.py --slug ozu-shakyo-kessan
python tools/check_numbers.py                    # 全記事
```

記事の数字を抜き、出典のURL・PDFを実際に取ってきて、その数字が出典の中にあるかを見ます。取ってきた出典は `tools/_source_cache/` に貯まります(.gitignore済み)。

**「見つからない=間違い」ではありません。** 自分で計算した割合や、表から言い換えた数字は当たらないのが普通です。人が見るべき数字を数百個から数個に絞るための道具です。「約1,930万円」のように**丸めた数字は最初から照合していません**(当たらなくて当然なので)。

**この道具に見抜けないもの:** 「数字は出典にあるが、意味が違う」(人口の28%減を世帯数の28%と取り違える等)。ここは人が読むしかありません。

### JavaScriptで中身を描くページ

入札情報サイトや環境省のページは、普通に取ってくると0字〜2000字のメニューしか手に入りません。そこから「数字が見つからない」と言っても意味がないので、**ブラウザで開き直して本文を取る**モードがあります。

```powershell
python tools/check_numbers.py --render
```

Playwrightを使います(`check_browser.py` と同じものなので追加の用意は不要)。取れた本文はキャッシュに上書きされるので、次からは普通の照合で使えます。

### 出典が後から書き換わっていないか(月次)

**公開したときは正しかった数字が、出典側の更新で古くなることがあります。** 何回点検しても、点検した時点では正しいので気づけません。ここは長らく盲点でした。

```powershell
python tools/check_numbers.py --index    # いまの出典の中身を控える(最初に1回)
python tools/check_numbers.py --watch    # 取り直して、変わっていないか見る(月次)
```

`--watch` は、中身が変わった出典と、**それを引いている記事**を一覧で出します。控えは `tools/source-index.json`(ハッシュと文字数だけ。本文は含みません)。

中身が変わっていても、記事の数字が変わったとは限りません(更新日の追記だけのこともある)。変わった出典が出たら、その記事の数字を確かめ直してください。

## 点検は自動で走ります(2026-08-29から)

`.claude/settings.json` に **Stop フック** を入れてあります。クロコが「できました」と言おうとした瞬間に、Claude Code 本体が `hook_check.py` を走らせます。

- 見るのは **いま手を入れたページだけ**(`git status` に出ているHTML)。既存の記事の警告で埋もれません。
- ルールから外れていたら、クロコは終われません。直すか、直さない理由を伝えるまで戻されます。
- **クロコが忘れても走ります。** ここが要点です。「完了と言う前に点検する」というルールは前から書いてありましたが、走らせるかどうかがクロコの判断に委ねられていました。判断を仕組みに置き換えたのがこのフックです。

フックの中身を見たり止めたりするには、Claude Code で `/hooks` と打ってください。

### 会議録を検索する(`gikai.py`)

```powershell
python tools/gikai.py 松下寿                  # 全期間(2008年〜)から探す
python tools/gikai.py 新幹線 --from 2020      # 2020年以降だけ
python tools/gikai.py 空き家 --list           # ヒットした会議の一覧だけ
```

大洲市議会の会議録は平成20年ごろから全文が公開されていて、**新聞記事より情報量が多く、しかも消えません**。松下寿の記事では、市長の生の言葉(「青天のへきれき」)、新聞に載っていない数字(有効求人倍率0.39倍)、どこにも書かれていなかった事実(「昭和48年 大洲市企業誘致条例によって誘致」)がここから出てきました。

取ってきた会議録は `tools/_gikai_cache/` に貯めます(.gitignore済み。GitHubには上げません)。消しても次に取り直すだけです。

ふだんの点検は `check_site.py` だけで十分です。`check_browser.py` は、デザインやレイアウトを変えたあと・月次点検のときに走らせてください(初回のみ `pip install playwright` と `playwright install chromium` が必要)。アクセス解析への通信は自動でブロックするので、何度走らせても本物のアクセス数は汚れません。

これまで「太字を付け忘れた」「出典欄のクラスが抜けた」「タイトルを直したのに記事一覧だけ古いまま」といったミスが、何度も繰り返し起きていました。人が目で見て防ぐには数が多すぎるので、機械に見張らせることにしたものです。

**ファイルは一切書き換えません。読むだけです。** 何度走らせても安全です。

## 使い方

PowerShellで、このリポジトリのフォルダに入ってから打ちます。

```powershell
# まずリポジトリのフォルダへ移動する
python tools/check_site.py
```

数秒で結果が出ます。

### いろいろな走らせ方

| やりたいこと | コマンド |
|---|---|
| ふつうに点検する | `python tools/check_site.py` |
| 出典URLが生きているかも見る(数分かかる) | `python tools/check_site.py --urls` |
| 1つの記事だけ見る | `python tools/check_site.py --slug ozu-mirai-note` |
| いま手を入れたページだけ見る | `python tools/check_site.py --changed` |
| 疑問形の見出しを一覧にする | `python tools/check_site.py --headings` |
| 点検器自体が壊れていないか確かめる | `python tools/check_site.py --selftest` |
| 結果をファイルに保存する | `python tools/check_site.py --json 結果.json` |

## 結果の読み方

```
  【構造】...................... OK
  【タイトル】.................. エラー 1件
  【匿名性】.................... OK
  【文字化け】.................. OK
  【出典】...................... エラー 9件
```

- **エラー** … 直した方がよいもの。読者に見える不具合か、決めたルールに反しているもの。
- **警告** … 見て判断するもの。直さなくても壊れません。

エラーがゼロなら、それは「もう見なくていい」という意味です。

## 何を見ているか

| 種類 | 中身 |
|---|---|
| 構造 | ヘッダー・出典欄・写真ブロック・スクリプトなど、必要な部品が揃っているか |
| タグ | `<div>` などの開き閉じが合っているか(合わないとレイアウトが崩れる) |
| 表 | 記事内の表がスクロール用の囲いに入っているか(無いとスマホで横にはみ出す) |
| タイトル | 記事の中の4か所と、記事一覧の台帳で、タイトルが一致しているか |
| 台帳 | 台帳にあるのにファイルが無い、という食い違いがないか |
| 匿名性 | 本名や勤務先が本文に出ていないか |
| 文字化け | 文字化け記号が混ざっていないか |
| 出典 | 2本以上あるか。すぐ消えるURLを使っていないか |
| スタイル | 見出し・太字が最低限あるか |
| 文体 | 大洲ノートが常体で統一されているか |
| 表現 | 「〜知ってほしい」のような取ってつけた呼びかけが入っていないか |
| 文章 | 1文が長くなりすぎていないか(150字超) |
| 要点 | 冒頭の要点ボックスが3行あるか |
| 事実 | 予讃線の記事で「電車」と書いていないか(非電化なので「列車」) |
| リンク | `--urls` のとき、出典URLが本当に生きているか |

**表現・文章・要点・事実の4つは、2026-08-29に足したものです。** それまでは記事のルール(`.claude/skills/kiji/`)に文章として書いてあるだけでした。実際に測ってみると、機械が見ている項目は147本中0本の違反、文章で頼んでいるだけの項目は違反が生き残っていました。この差が、ルールを機械に移した理由です。

**新しいルールを決めたら、機械にできる形かどうかをまず考えてください。** できるなら、ここに足すのが一番確実です。

## 「OK」を信用してよいのか

点検器そのものが壊れていたら、何も見つけずに「OK」と言い続けてしまいます。それを防ぐのが自己診断です。

```powershell
python tools/check_site.py --selftest
```

わざと壊したページを一時的に作って、**17項目すべてを検知できるか**を確かめます。ここが通らないうちは、点検結果を信用しないでください。

検査を足したら、この自己診断にも同じだけ項目を足してください。足さないと「見ているつもりで見ていない検査」が育ちます。

サイトの作りを大きく変えたあとは、これを走らせてください。

## わざと見逃しているもの

- **`book/`(大洲と読書)が敬体なのは、わざとです。** 常体で統一する方針なのは大洲ノート(`eachnews/`)だけなので、book には常体チェックを掛けていません。
- **実在の地名や学校名が引っかかることがあります。**記事の内容として正当なものは、検査の対象から除外しています。除外の指定はリポジトリ外の語リストに書いてあります。

## 基準を変えたいとき

`check_site.py` の上のほうに、設定がまとまっています。

```python
MIN_SOURCES = 2    # 出典は2本以上
MIN_H2 = 2         # 見出しの最低数
MIN_STRONG = 1     # 太字の最低数
MAX_SENTENCE = 150 # 1文がこれを超えたら長すぎる
SUMMARY_LINES = 3  # 冒頭の要点ボックスの行数
```

「出典は3本以上にしたい」と思ったら、`MIN_SOURCES = 3` に変えるだけです。クロコに「出典3本以上に変えて」と言ってもらっても構いません。
